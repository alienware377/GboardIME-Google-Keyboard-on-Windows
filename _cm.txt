Restore multi-word swipe-delete; watchdog checks the ADB link too

Multi-word swipe-delete (regression from the forward-delete fix):
The shadow padding installed after a reposition was a FLAT RUN OF SPACES.
Gboard's swipe-on-backspace deletes by WORD, and a pure-whitespace run has no
word boundaries, so Gboard selected the entire run and every swipe - short or
long - collapsed to a single Ctrl+Backspace on Windows.
- Padding is now built from invisible fake WORDS: NBSP (U+00A0) bodies with real
  spaces as separators. It still renders completely blank, but it tokenizes, so
  the fake words consumed by a swipe can be counted and forwarded as exactly
  that many KEY:CTRL+BACKSPACE (the host's *N repeat suffix already supported it).
- NBSP is written as (char) 0x00A0, never a literal char or a unicode escape:
  Java's lexer rewrites those everywhere, which makes compilation charset
  dependent and leaves invisible characters in the source.
- SAFETY CLAMP: if the deleted region reaches either edge of the buffer, Gboard
  may have selected everything on that side rather than what the user swiped, so
  that case falls back to ONE word. Over-deleting is unrecoverable;
  under-deleting is a trivial retry. Re-centering keeps words of headroom on both
  sides so real swipes never reach the edge.
- Word counting is source-aware (the TextWatcher path must count against the
  PRE-edit text, since it runs after the buffer already changed).
- Fixed alongside: an empty SYNC (host read an empty field, or could not read an
  Electron field at all) wiped the padding and re-greyed the whole editing panel;
  it now falls back to the padding instead.

Watchdog: process-alive is not health.
The ADB reverse tunnel can vanish independently of the host (adb server restart,
another tool running a reverse --remove-all), after which the relay retries
forever while every process still looks healthy - the keyboard is simply dead.
- Check an established connection on the host port every ~15s (cheap, no adb) and
  repair after 2 consecutive failures: re-apply the tunnel, then restart the relay
  app if it still has not dialled back.
- ALSO verify the mapping itself via reverse --list every ~60s: an existing socket
  keeps working after the mapping is removed, so a live connection does not prove
  the tunnel is there - it only breaks at the next reconnect.
- Every adb call is wrapped in a real WaitForExit(ms) timeout.
- Single-instance is now a named MUTEX. Matching the command line for the script
  name also matched any shell that merely MENTIONED the script (a diagnostic
  one-liner, an installer), so the real watchdog deferred to a phantom and exited,
  leaving nothing running. The stop script's kill filter now requires -File <path>
  for the same reason.

Verified live: removing the tunnel entry is detected and restored automatically.
